## 0. 結論摘要

### 0.1 可以可靠計算還原因子的事件類型

| 事件類型 | 市場 | 官方來源 | 因子 | 驗證樣本 |
| --- | --- | --- | --- | --- |
| 現金股利（除息） | TWSE | `TWT49U` | `減除股利參考價 / 除權息前收盤價` | 2412 / 1101 / 2382 / 2357 / 0056 |
| 現金股利（除息） | TPEx | `exDailyQ` | 同上（欄位直接提供） | 2025 全年 1250/1250 筆重算相符 |
| 股票股利（無償配股） | TWSE | `TWT49U` (+`TWT49UDetail`) | 同上 | 1773 / 6423 |
| 股票股利（無償配股） | TPEx | `exDailyQ` | 同上 | 同 2025 全年重算 |
| 減資（彌補虧損 / 退還股款） | TWSE | `TWTAUU` | `恢復買賣參考價 / 停止買賣前收盤價格` | 2412 (2011-01-25) |
| 減資 | TPEx | `revivt` | 同上（同欄位語意） | 欄位對應確認，未逐筆重算 |
| 面額變更 / 分割 | TWSE | `TWTB8U` | `恢復買賣參考價 / 停止買賣前收盤價格` | 8070 / 2327 |

### 0.2 必須標 `data_insufficient`

| 項目 | 原因 |
| --- | --- |
| TPEx 下市（終止櫃檯買賣）歷史清單 | 官方端點只回當年度資料，找不到歷史封存 → **PIT universe 無法在 TPEx 端消除 survivorship bias** |
| TPEx 面額變更 | 本次未在 TPEx 找到對應端點；不宣告「官方無此資料」，只記錄「本次未找到」 |
| 除息併案辦理減資的現金股利金額 | 只出現在 `TWTAUU` 的自由文字 `notes`，無結構化欄位 |
| 尚未定價的減資恢復買賣列 | 價格欄位為 `-`（調查當日 2 筆：2323 中環、4155 訊映） |
| 現金增資認購價 | TPEx 觀察到非數值字串 `註4`（6129 普誠, 115/10/07） |
| 2003-05-05 以前的除權息 | TWSE 明確拒絕查詢 |
| 2011 以前的 TWSE 減資 / 2013 以前的 TPEx 減資 | 官方查詢無資料 |
| `available_at` / `published_at` | 五張表的 payload 都沒有發布時間欄位 |
| 成交量還原 | 本次**沒有**以真實資料驗證，不給公式 |
| 總報酬（股利再投入）因子 | TWSE `權息` 列無法只用 `TWT49U` 拆出現金股利 |

### 0.3 一句話結論

> **台股每一種價格事件，官方都同時公布「事件前收盤價」與「事件後參考價」。
> 還原因子是這兩個官方欄位的比值，是量測值，不是推導值。**
>
> 唯一需要判斷的是「用哪一個參考價」——見 §2.3，答案是 `減除股利參考價`，不是 `除權息參考價`。

## 1. 官方來源清單（實測 endpoint 與欄位）

### 1.1 TWSE 除權除息計算結果表 — `TWT49U`

```
GET https://www.twse.com.tw/rwd/zh/exRight/TWT49U?startDate=20250101&endDate=20251231&response=json
```

實際 `fields`（15 欄）：

```
資料日期, 股票代號, 股票名稱, 除權息前收盤價, 除權息參考價, 權值+息值, 權/息,
漲停價格, 跌停價格, 開盤競價基準, 減除股利參考價, 詳細資料,
最近一次申報資料 季別/日期, 最近一次申報每股 (單位)淨值, 最近一次申報每股 (單位)盈餘
```

payload 另有 `formula` 與 `notes` 兩個陣列，**官方公式直接寫在裡面**（原文）：

```
除權息參考價  = (除權息前收盤價 - 息值 + 現金增資認購價*現金增資配股率) / (1 + 無償配股率 + 現金增資配股率)
減除股利參考價 = (除權息前收盤價 - 息值) / (1 + 無償配股率)
權值+息值     = 除權息前收盤價 - 除權息參考價
```

`notes` 中三條關鍵限制（原文）：

- 「股利資料自民國92年5月5日起開始提供」
- 「本表不含除息併案辦理退還股款減資或分割減資之資料」
- 「開盤競價基準：當不含現金增資除權時，取最接近除權息參考價之檔位價，遇含現金增資除權時，則取最接近減除股利參考價之檔位價。」

**歷史覆蓋（實測，非推測）**

| 查詢起日 | 回應 |
| --- | --- |
| 1995 / 2000 / 2002 / 2003-01-01 | `stat = 查詢開始日期小於92年5月5日，請重新查詢!`，0 rows |
| 2003-05-04 | 同上，被拒 |
| **2003-05-05** | `stat = OK`，458 rows，首列 `92年05月05日` |
| 2004 全年 | `OK`，508 rows |
| 2025 全年 | `OK`，1358 rows |
| 2015-01-01 ~ 2025-12-31 | `OK`，10,483 rows，**單一請求** |

→ **實測覆蓋起日 = 2003-05-05（民國92/05/05），邊界精確到日。**

2025 事件分佈：`息` 1227、`權` 66、`權息` 65。
2015–2025 共 10,483 筆，`(股票代號, 資料日期)` **零重複**。

```

```

`fields`：

```
股票代號, 股票名稱, (每股配發現金股利)除息, (增資配股) 除權,
A. 按普通股股東持股比例每千股無償配股, B. 員工紅利轉增資, C. (有償) 現金增資,
```

### 1.6 TWSE 減資恢復買賣參考價格 — `TWTAUU`

```
GET https://www.twse.com.tw/rwd/zh/reducation/TWTAUU?startDate=20110101&endDate=20261231&response=json
fields: 恢復買賣日期, 股票代號, 名稱, 停止買賣前收盤價格, 恢復買賣參考價,
        漲停價格, 跌停價格, 開盤競價基準, 除權參考價, 減資原因, 詳細資料
```

`formula`（官方原文）：

```
退還股款：               恢復買賣參考價 ＝（停止買賣前收盤價 - 息值 - 每股退還股款）/（減資換股率）
彌補虧損：               恢復買賣參考價 ＝（停止買賣前收盤價）/（減資換股率）
彌補虧損之減資並現金增資： 恢復買賣參考價 ＝（停止買賣前收盤價）/（減資換股率）
                         減資後現金增資除權參考價 ＝（恢復買賣參考價 + 現金增資認購價 * 減資後現金增資配股率）
                                                 /（1 + 減資後現金增資配股率）
```

**注意：`減資換股率`、`每股退還股款`、`息值` 都不是本表的欄位。**
公式公布了，但輸入取不到 → 只能用「前收 / 參考價」兩個欄位的比值，見 §2.4。

## 2. 還原因子推導與驗證

### 2.1 第一件被驗證的事：`除權息前收盤價` 就是官方前一交易日收盤價

用 `STOCK_DAY` 對四檔樣本逐筆比對：

| 代號 | 除權息日 | `TWT49U.除權息前收盤價` | `STOCK_DAY` 前一交易日收盤 | 一致 |
| --- | --- | --- | --- | --- |
| 2412 中華電 | 114/07/03 | 134.50 | 114/07/02 → 134.50 | ✓ |
| 2330 台積電 | 114/03/18 | 970.00 | 114/03/17 → 970.00 | ✓ |
| 6658 聯策 | 114/01/06 | 76.80 | 114/01/03 → 76.80 | ✓ |
| 1605 華新 | 114/06/04 | 20.90 | 114/06/03 → 20.90 | ✓ |

→ 因子的分母可以用我們自己的 daily store 交叉驗證，不需要盲信官方表。

### 2.2 官方公式可被完整重現（含明細拆解）

用 `TWT49UDetail` 取出 `現金股利 / 無償配股 / 現金增資股數 / 認購價 / 原股東每千股認購`，
反推 `參與除權之發行股數 N = 原股東認購股數 ÷ (按股東持股比例每千股認購 ÷ 1000)`，
再代入 §1.1 官方公式並**無條件捨去到小數第 2 位**：

| 代號 | 日期 | 現金股利 | 無償配股率 | 現增配股率 | 官方 `減除股利參考價` | 重算 | 官方 `除權息參考價` | 重算 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1773 | 114/06/13 | 2.5 | 0.20000000 | 0 | 123.75 | 123.75 ✓ | 123.75 | 123.75 ✓ |
| 2545 | 114/06/17 | 4.5 | 0 | 0.15866250 | 47.20 | 47.20 ✓ | 46.00 | 46.00 ✓ |
| 6658 | 114/01/06 | 0 | 0 | 0.10648007 | 76.80 | 76.80 ✓ | 75.66 | 75.66 ✓ |
| 6423 | 114/06/12 | 0 | 0.02030000 | 0 | 88.01 | 88.01 ✓ | 88.01 | 88.01 ✓ |

1605 華新另外單獨核對：現金股利 0.5、無償 0、現增 400,000,000 股 @ 20 元、
原股東認購 320,000,000 股、每千股認購 79.37821165
→ `N = 4,031,082,000`、現增配股率 `0.0992228`
→ 參考價 `20.363893` → 截斷 `20.36`（官方 20.36 ✓）
→ `權值+息值 = 20.90 − 20.363893 = 0.536107`（官方 `0.536107` ✓，**六位小數完全相符**）。

**推論出的兩條結構事實**：

1. `除權息參考價 = trunc2(除權息前收盤價 − 權值+息值)`（截斷，不是四捨五入）。
   2330 佐證：`970.00 − 4.50002 = 965.49998` → 官方 `965.49`。
2. `權值+息值` 是**未截斷前**的差額，精度 6 位小數，比 `參考價` 高。

TPEx 端不需要明細端點就能重現：
對 2025 全年 **1250 筆逐筆重算** `trunc2((除權息前收盤價 − 現金股利) ÷ (1 + 每仟股無償配股 ÷ 1000))`
與官方 `減除股利參考價` 比對 → **OK 1250 / MISMATCH 0**。

### 2.3 關鍵判定：用 `減除股利參考價`，不是 `除權息參考價`

2025 年 TWSE 1358 筆中：

- `減除股利參考價 == 除權息前收盤價` 者 **43 筆** → 這些事件只有現金增資，無股利、無無償配股。
- `減除股利參考價 != 除權息參考價` 者 **49 筆** → 含現金增資。

拿 6658 聯策（現金增資、現金股利 0、無償配股 0）驗證市場真實行為：

```
114/01/03  O 74.60  H 80.50  L 74.30  C 76.80     ← 除權前一日
114/01/06  O 76.60  H 80.80  L 76.00  C 76.00     ← 除權日
官方: 除權息前收盤價 76.80 / 除權息參考價 75.66 / 減除股利參考價 76.80 / 開盤競價基準 76.80
```

除權日開盤 76.60、最高 80.80，**價格完全沒有因為 1.48% 的「權值」跳空**。
開盤競價基準取的是 `減除股利參考價 = 76.80`，不是 `除權息參考價 = 75.66`。

> **若採用 `除權息參考價 / 前收` 當因子，會在還原序列中憑空製造 −1.48% 的假報酬。**

原因是現金增資的認購權利是**另一檔有價證券**，不是原股的價格事件；
`除權息參考價` 是「假設股東全額認購」後的理論權益值，不是原股的交易基準。

1605 華新（權息 + 現增）同向佐證：`減除股利參考價 20.40` vs `除權息參考價 20.36`，
`開盤競價基準 20.40`，除權日 O 20.50 / L 20.45，貼合 20.40 基準。

### 2.4 Authoritative 還原因子（本次唯一結論）

令 `C_prev` = 事件前收盤價、`P_ref` = 事件後官方參考價。

```
f(D) = P_ref(D) / C_prev(D)
```

各事件類型的欄位對應：

| 事件 | 來源 | `C_prev` | `P_ref` |
| --- | --- | --- | --- |
| TWSE 除權息 | `TWT49U` | `除權息前收盤價` | **`減除股利參考價`** |
| TPEx 除權息 | `exDailyQ` | `除權息前收盤價` | **`減除股利參考價`** |
| TWSE 減資 | `TWTAUU` | `停止買賣前收盤價格` | `恢復買賣參考價` |
| TPEx 減資 | `revivt` | `最後交易日之收盤價格` | `減資恢復買賣開始日參考價格` |
| TWSE 面額變更 | `TWTB8U` | `停止買賣前收盤價格` | `恢復買賣參考價` |

除權息事件另有**高精度等價形式**（已於 §2.2 驗證，避開 `P_ref` 的 2 位小數截斷）：

```
f = (C_prev − cash_dividend) / (C_prev × (1 + free_share_ratio))
```

- TPEx：`cash_dividend = 現金股利`、`free_share_ratio = 每仟股無償配股 ÷ 1000`，**直接可得**。
- TWSE：需 `TWT49UDetail`（每事件 1 次 HTTP）。
- 當事件不含現金增資時（`減除股利參考價 == 除權息參考價`），可用 6 位小數的
  `f = 1 − (權值+息值) ÷ 除權息前收盤價`，**不需要明細端點**。

截斷誤差是真實且會累積的。0056 元大高股息 2025 年 4 次配息，
`P_ref/C_prev` 與 `1 − (權值+息值)/C_prev` 每次相差約 `1.1e-4`
（例：114/07/21 `0.97556180` vs `0.97567416`）；季配 ETF 十年 40 次事件 → 累積偏離約 0.4%。

後復權序列：

```
adjusted(t) = raw(t) × Π f(D)    for all events D with event_date(D) > t
```

### 2.5 `adjusted_open / high / low` 可以用同一個比例嗎？

**可以，同一個 `f` 直接等比縮放 O / H / L / C。**

理由是結構性的：事件邊界落在兩個交易日之間，同一交易日的 O/H/L/C 位於同一個
股數 / 面額基準上，`f` 是純粹的計價基準重新縮放，對四個價格一視同仁。
本次沒有找到任何官方欄位暗示 O/H/L 需要不同處理。

**但有一條硬界線**：漲跌停判定**不得**使用還原價。
8070 長華 10:1 面額變更恢復買賣當日（109/08/17）O=H=L=C=20.90，
正好等於官方 `恢復買賣參考價 19.00 × 1.10`。漲停只有在原始價 + 官方
`開盤競價基準` 上才成立，這與 `CONTRIBUTING.md §3.2` 既有規定一致。

**成交量：本次未驗證，不給公式。**
面額變更與減資改變流通股數，理論上量需要反向縮放，但 8070 恢復買賣當日
成交量 571,134（漲停鎖死、量能不具代表性），次日才跳到 50,700,069。
單一樣本無法區分「面額換算」與「事件後真實爆量」→ 標 `data_insufficient`，
需另以多樣本專門驗證。

### 2.6 多個事件同日發生時的合成順序

**實測結果：TWSE 2015–2025 期間，同一 `(股票代號, 日期)` 不會同時出現在兩張表。**

| 比對 | 事件數 | 同日重疊 |
| --- | --- | --- |
| `TWT49U` × `TWTAUU` | 10,483 × 301 | **0** |
| `TWT49U` × `TWTB8U` | 10,483 × 10 | **0** |

這與 `TWT49U` 的 notes 一致：「本表不含除息併案辦理退還股款減資或分割減資之資料」。
減資與面額變更都伴隨**停止買賣數日**，本質上不可能與除權息同日。

因此：

1. 跨日事件的合成就是因子連乘，乘法可交換，**無順序問題**。
2. 同日多事件在 2015–2025 的官方資料中**不存在**，不需要合成規則。
3. 唯一有內部順序的是「減資併現金增資」（`TWTAUU` 中 3 列，`除權參考價` 非 `--`）。
   官方公式已定義順序：**先減資求 `恢復買賣參考價`，再以該價為基礎算現增除權參考價**。
   價格連續性應採第一步的 `恢復買賣參考價`（理由同 §2.3：現增不是原股價格事件）。
4. 若同一日在 `TWTAUU` 出現重複列（實測 2 組），先 dedup by `(代號, 恢復買賣日期)` 再取值；
   已核對重複列的價格欄位完全相同。

## 3. Event date 與 Ex-date 的定義與差異

| 事件 | 官方日期欄位 | 語意 | 與前收的關係 |
| --- | --- | --- | --- |
| 除權息 | `資料日期` / `除權息日期` | **就是 ex-date**：當日起交易不含權息 | `除權息前收盤價` = 前一**交易日**收盤 |
| 減資 | `恢復買賣日期` | **復牌日，不是 ex-date** | `停止買賣前收盤價格` = **停牌前最後一個交易日**收盤，中間有數日無資料 |
| 面額變更 | `恢復買賣日期` | 同上 | 同上 |

實測證據（`STOCK_DAY`）：

```
2412 中華電（退還股款減資，恢復買賣 100/01/25）
  100/01/06  C 73.10           ← 停止買賣前最後交易日；TWTAUU 停止買賣前收盤價 = 73.10 ✓
  100/01/07 ~ 100/01/24        ← 完全沒有交易列（停止買賣）
  100/01/25  O 90.40  C 89.20  ← 恢復買賣；TWTAUU 恢復買賣參考價 = 88.87

2327 國巨（面額 4:1，恢復買賣 114/08/25）
  114/08/13  C 546.00          ← TWTB8U 前收 546.00 ✓
  114/08/14 ~ 114/08/22        ← 停止買賣
  114/08/25  O 142.00          ← 參考價 136.50 = 546.00 ÷ 4

8070 長華（面額 10:1，恢復買賣 109/08/17）
  109/08/05  C 190.00          ← TWTB8U 前收 190.00 ✓
  109/08/17  O=H=L=C 20.90（漲停） ← 參考價 19.00 = 190.00 ÷ 10
```

**對 backfill 的直接影響**：減資 / 面額變更的「前一交易日」**不能**用日曆或交易日曆往前推一天，
必須以官方 `停止買賣前收盤價格` 為準，或在自有 daily store 中取「上一筆有資料的交易日」。

### 6.1 TWSE 終止上市公司 — **可用**

  2009:3 / 2010:12 / 2011:8 / 2012:6 / 2013:7 / 2014:7 / 2015:8 / 2016:10 / 2017:8 / 2018:10 /

| --- | --- | --- |

`?date=110/01/01` 與 `company/deListedHis` 皆 302。

### 6.3 對 survivorship bias 的實際結論

1. **TWSE**：可用官方 CSV 建立 2001 起的下市清單 → 2015 起的 PIT universe 可做到無偏。
2. **TPEx**：官方端找不到歷史清單。可行的替代路線（依可信度排序，本次皆未實作）：
   - 從每日全市場快照（`exDailyQ` / `dailyQuotes`）回補：symbol 連續消失且未復牌 → 推定下櫃。
     這是**推論**，`status` 必須標 `inferred`，不得標 `official`。
   - MOPS 重大訊息（本 repo 已有 exact-timestamp 管線）中的終止上櫃公告。
   - 第三方資料源，必須標 `third_party_fallback`。
3. **目前 repo 的 universe 本身就是 survivorship-biased**：
   `app/taiwan/universe/models.py:59` 定義
   `listing_status: "active" | "delisted" | "suspended" | "unsupported"`，
   但 `app/taiwan/universe/adapters.py` 的建構點（237 / 247 / 254 / 401 / 424 行）
   **只會寫入 `"active"` 或 `"unsupported"`，從不寫 `"delisted"`**。
   下市清單接進來之前，任何 `pit_universe` 都只是「今天還活著的股票」。

## 8. Corporate Action Adjustment Is A Market-Data Transformation, Not A Predictive Feature

> 本節為 A1.5 補充。§5 已確認五張官方表都沒有 `published_at`，
> 因此 `available_at=null`。本節說明**為什麼這件事不應該讓所有價格類 feature
> 都被 training eligibility 擋掉**，以及界線畫在哪裡。

### 8.1 兩種完全不同的東西

必須嚴格區分：

| | 1. Adjustment / price normalization | 2. Predictive corporate-action feature |
| --- | --- | --- |
| 是什麼 | 把同一檔股票在事件前後的**計價基準**統一 | 用「將要除息 / 已公告股利」去預測未來報酬 |
| 例子 | `adjusted_close`、`pit_return`、MA / RS / momentum 的輸入 | 「即將除息」、「公告股利率」、「除息殖利率排序」 |
| 時間語意 | **`effective_at`**（事件在市場上生效的時刻） | **`available_at`**（公告在市場上可得的時刻） |
| 需要 verified `available_at` 嗎 | **不需要** | **需要** |
| 理由 | 事件生效本身就是公開、可觀察的價格不連續；不知道公告時間不影響「T 時點的價格基準是什麼」 | 這是在賭資訊優勢，必須證明該資訊在 T 已公開 |

### 8.2 `effective_at` 的定義（本 repo 採用）

```
除權息 (ex_dividend)          effective_at = ex-date 開盤
減資 (capital_reduction)       effective_at = 恢復買賣日開盤
面額變更 (par_value_change)    effective_at = 恢復買賣日開盤
```

依據：`開盤競價基準` 是該日開盤集合競價的法定基準價，必須先於開盤存在（§5）。
這是**市場機制的必然**，與「公告何時發出」無關，因此可以確定地寫下 `effective_at`，
而 `available_at` 仍然維持 `null`、policy 仍然維持 `market_mechanism_inferred`，
**不得升級為 `verified`**。

### 8.3 Feature 生成規則（as-of T）

```
建立 T 時點的 adjusted feature window 時：
    只允許使用 effective_at <= T 的 corporate actions
```

明確禁止：

> 建立一條使用 2026 年 corporate action、回頭餵給 2018 年 feature generation 的
> **全域 future-aware adjusted series**。

也就是 §2.4 的後復權公式**不可以**直接拿來做 feature。
它只適用於「今天回看歷史」的展示用途。Feature 端必須是 as-of 錨定的：

```
presentation (圖表/研究頁)   adjusted(t) = raw(t) × Π f(D)              for all D > t
                             → 使用全部已知事件，含 T 之後的未來事件
                             → quant_eligible = false

PIT feature (as-of T)        adjusted(t | T) = raw(t) × Π f(D)          for t < D <= T
                             → 只用 T 當時已生效的事件
                             → 加入一個 T 之後的新事件，不得改變任何 t <= T 的結果
```

註：報酬率對錨點不敏感 —— 期間 `(t-1, t]` 的報酬只取決於**當日**事件，
因此 `pit_return` 在任何 `T >= t` 下都相同。這是可以寫 regression test 的不變量。

### 8.4 Label 端（T → T+5）

**允許**使用 label horizon 內實際發生的 corporate action。

理由：label 是 **realized forward outcome**，不是 feature。
T+5 的實際報酬本來就必須把 T→T+5 之間的除權息還原進去，
否則 label 會把除息跳空誤記成虧損。這不是洩漏，這是正確計算已實現報酬。

界線：

```
feature 端   只能看 effective_at <= T
label 端     可以看 effective_at <= T + horizon
```

兩者用**不同的 as-of**，但必須用**同一個 corporate-action 正規化實作**（單一真相層）。

### 8.5 結論

```
available_at = null
availability_policy = "market_mechanism_inferred"
```

**不應該**讓 `adjusted_close` / `pit_return` / momentum / RS / label 被 training eligibility 擋掉，
因為它們消費的是 `effective_at`，不是 `available_at`。

但只要未來把下列任何一項當成 **predictive feature**：

- 「即將除息」/「距離除息天數」
- 「已公告股利金額 / 殖利率」
- 「董事會決議配息」

就**仍然需要 verified `available_at`**。
本 repo 已有的 `app/taiwan/dividend_events.py`（MOPS 重大訊息，精確到秒、identity 穩定）
是唯一能提供該證據的來源；五張計算結果表不行。

這個 policy exception 的範圍僅限 **corporate-action price normalization**，
**不得**自動延伸到財報、月營收、法人買賣超、新聞等任何 alpha feature。

## 9. Volume adjustment policy

§2.5 已判定成交量還原 `data_insufficient`（單一樣本 8070 在恢復買賣當日漲停鎖死，
無法區分「面額換算」與「事件後真實爆量」）。本節把它定成明確規則：

1. **不推導 volume adjustment 公式。** 在有多樣本驗證之前，本 repo 不提供還原量。
2. **不修改 raw volume。** 儲存與讀取的 `volume` 永遠是官方原始股數。
3. **流動性 eligibility 優先使用 `amount`（成交金額 TWD）/ ADV20 TWD**，
   而不是股數。金額不受股數變動影響，跨 split / 減資 仍可比較。
4. **share-count-changing event 的 lookback 守則**：
   若某個 volume-based factor 的 lookback window 跨過
   股票股利（無償配股）、面額變更、或減資等會改變流通股數的事件，
   在沒有 validated volume adjustment 之前，
   **該 factor 在該 symbol / 該日期必須標 `data_insufficient` / `unavailable`**，
   **不得靜默用 raw volume 直接比較**。

   判定所需的事件日期，來自本文件 §1 的五張官方表：
   `每仟股無償配股 > 0` 的除權息、全部 `TWTAUU` / `revivt` 減資、全部 `TWTB8U` 面額變更。

5. 金額型因子（成交金額、周轉金額、ADV20 TWD）**不受**本限制。
